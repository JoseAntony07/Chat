# Android Emulator and Android Studio Guide

This guide explains how to set up and run Convo Mobile on Android using either Expo CLI or Android Studio. Both workflows build the same React Native app and connect to the same Django backend. This project uses Expo SDK 57 and a native development build; do not use Expo Go for these steps.

For iOS, see [IOS_XCODE_GUIDE.md](IOS_XCODE_GUIDE.md). For the overall mobile setup, see [README.md](README.md).
For installing on a real phone, see [PHYSICAL_DEVICE_README.md](PHYSICAL_DEVICE_README.md).

## 1. Install Android development tools on macOS

1. Install and open **Android Studio**. Complete the Setup Wizard and choose the Standard installation.
2. Open **Android Studio → Settings → Languages & Frameworks → Android SDK** (on some versions: **Settings → Android SDK**).
3. Under **SDK Platforms**, install **Android 16 / API 36**. Under **SDK Tools**, install **Android SDK Build-Tools**, **Android SDK Platform-Tools**, and **Android Emulator**. Install Android SDK Command-line Tools if Android Studio offers them.
4. Install Java 17 if it is not available on your Mac. Expo's Android setup guide uses Azul Zulu 17:

   ```bash
   brew install --cask zulu@17
   ```

5. In Android Studio, open **Tools → Device Manager → Create Virtual Device**. Pick a Pixel device, download an Android 16 / API 36 system image, and create the emulator. On Apple Silicon, choose an **ARM 64** image. Start the emulator from Device Manager.

Android Studio may install the SDK under `~/Library/Android/sdk`. Check the **Android SDK Location** field in Android Studio if yours is different. In `~/.zshrc`, set the SDK tools on your terminal path (replace the SDK path if Android Studio shows a different one):

```bash
export ANDROID_HOME="$HOME/Library/Android/sdk"
export PATH="$PATH:$ANDROID_HOME/platform-tools:$ANDROID_HOME/emulator"
export JAVA_HOME=$(/usr/libexec/java_home -v 17)
```

Reload the shell and confirm the tools are available:

```bash
source ~/.zshrc
adb --version
java -version
```

## 2. Install the app and configure the backend URL

If you use nvm, select the Node version from `mobile/.nvmrc` first:

```bash
cd mobile
nvm install
nvm use
```

If you do not use nvm, skip those commands and select Node 24 with your installed Node manager. Then install the app dependencies and create the local environment file:

```bash
cd mobile
node --version
npm install
cp .env.example .env
```

Edit `mobile/.env` for an Android Emulator:

```env
EXPO_PUBLIC_API_URL=http://10.0.2.2:8000/api
EXPO_PUBLIC_WS_URL=ws://10.0.2.2:8000
```

`10.0.2.2` is the Android Emulator's special address for reaching a service on the Mac. Do not use `127.0.0.1` for the Android Emulator; that address points back to the emulator itself.

For reference:

| Target | API URL | WebSocket URL |
| --- | --- | --- |
| Android Emulator | `http://10.0.2.2:8000/api` | `ws://10.0.2.2:8000` |
| iOS Simulator | `http://127.0.0.1:8000/api` | `ws://127.0.0.1:8000` |
| Physical phone | `http://MAC_WIFI_IP:8000/api` | `ws://MAC_WIFI_IP:8000` |

For a physical phone, use the Mac's Wi-Fi IP (`ipconfig getifaddr en0`), connect the phone and Mac to the same Wi-Fi, and configure Django to allow that address and WebSocket origin. Expo `EXPO_PUBLIC_` values are visible in the app; never store secrets in them.

## 3. Start Django and Metro

Start Django from the repository's `backend/` folder. For Android Emulator or a phone, bind Daphne to all network interfaces so the device can reach it:

```bash
cd backend
source .venv/bin/activate
python -m daphne -b 0.0.0.0 -p 8000 config.asgi:application
```

Make sure `backend/.env` includes `10.0.2.2` in `ALLOWED_HOSTS`. If the WebSocket handshake is rejected, check `WEBSOCKET_EXTRA_ALLOWED_ORIGINS` in `backend/.env` and the Django terminal logs. The backend and Redis instructions are in the root [README](../README.md).

Start Metro from another terminal in `mobile/`:

```bash
cd mobile
npx expo start --dev-client
```

Keep Django and Metro running while testing. After editing `mobile/.env`, stop and restart Metro with cache clearing:

```bash
npx expo start --dev-client --clear
```

## 4. Option A: build and launch with Expo CLI

Start an Android Emulator from Android Studio's **Device Manager**, then from `mobile/` run:

```bash
npx expo run:android
```

Expo generates the native Android project if it is missing, compiles the app with the Android SDK, installs it on the running emulator, opens it, and starts or reuses Metro. The first native build may take several minutes. After it finishes, use the app in the emulator window.

If more than one emulator or device is connected, list them with:

```bash
adb devices
```

Then select one explicitly:

```bash
npx expo run:android --device "Emulator Name"
```

## 5. Option B: build and launch from Android Studio

The Android project is generated by Expo and does not exist in a fresh checkout until prebuild runs. From `mobile/`, generate it once:

```bash
npx expo prebuild --platform android
```

Then:

1. Open Android Studio and choose **Open**.
2. Select the `mobile/android` folder (the folder containing `settings.gradle`), not the repository root.
3. Wait for Gradle sync to finish. If Android Studio asks to install a missing SDK component, install it.
4. Start the emulator in **Tools → Device Manager**.
5. Start Metro in a separate terminal with `npx expo start --dev-client` from `mobile/`.
6. In Android Studio, select the **app** run configuration and the emulator, then click **Run ▶**.

Android Studio builds and installs the native Android app. It does not start Django or Metro; keep those terminal processes running. You can edit JavaScript/TypeScript while Metro is active and use Fast Refresh without rebuilding the native app.

## 6. Rebuild and cleanup

### Normal JavaScript changes

Keep Metro running. React Native JavaScript and TypeScript changes should load through Fast Refresh; no Android Studio build is normally needed.

### Native dependency or app configuration changes

After adding/changing a native dependency, changing native Expo config in `app.json`, or upgrading Expo, regenerate the native project and rebuild:

```bash
cd mobile
npx expo prebuild --clean --platform android
npx expo run:android
```

`prebuild --clean` deletes and recreates the generated `android/` folder. Do not keep manual changes there; configure native behavior in `app.json` or an Expo config plugin. Expo's [local build guide](https://docs.expo.dev/guides/local-app-development/) describes when to regenerate and rebuild.

### Clean Android build output

From `mobile/`:

```bash
cd android
./gradlew clean
cd ..
npx expo run:android
```

This removes generated Gradle build outputs. The next build recompiles them and takes longer.

If Android Studio has a stale Gradle sync, use **File → Sync Project with Gradle Files**, then build/run again. If Android Studio is holding a stuck Gradle process, close the build and run:

```bash
cd mobile/android
./gradlew --stop
```

## 7. Troubleshooting

- **No emulator/device found:** start an AVD in Device Manager and check `adb devices`.
- **App cannot reach Django:** confirm Daphne is running on port 8000, the emulator `.env` URLs use `10.0.2.2`, and Django permits that host. Restart Metro after `.env` changes.
- **WebSocket rejected:** check Daphne logs and `WEBSOCKET_EXTRA_ALLOWED_ORIGINS` in `backend/.env`.
- **Java version/build-tools errors:** check `java -version`, Android Studio's Gradle JDK setting, and the installed SDK Platform 36 and SDK Build-Tools.
- **Native project missing:** run `npx expo prebuild --platform android` from `mobile/`.
- **Stale or broken Android project:** run `npx expo prebuild --clean --platform android`, then rebuild.
