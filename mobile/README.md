# Convo Mobile

Convo Mobile is the React Native app for iOS and Android. It uses the same Django backend, accounts, conversations, message history, and WebSocket messaging as the web app.

## Requirements

- macOS for the iOS Simulator.
- Node.js 24 (the repository's `.nvmrc` selects version 24). npm is installed with Node; nvm is optional. If you already manage Node another way, use a Node 24 release. Node 23 is outside the supported range for this app's Expo and React Native packages and may print `EBADENGINE` warnings.
- Xcode installed from the Mac App Store or Apple Developer downloads. Open Xcode once and accept its license/setup prompts.
- CocoaPods for iOS native dependencies. If it is missing and you use Homebrew, install it with `brew install cocoapods`.
- The iOS Simulator runtime and device you want to run. In Xcode open **Settings → Components** (some Xcode versions label this **Platforms**) and download an iOS runtime if it is not already installed. The simulator used during development is **iPhone 18 Pro / iOS 27**.
- Python and the backend dependencies; see the repository [README](../README.md) for backend setup.
- Docker Desktop only if you want to use Redis locally. Redis is optional for single-process local development.

Xcode and the iOS Simulator are Apple tools. Expo Go is not needed for this project: it has native modules and iOS scene support configured, so run it as a development build in the simulator.

## First-time setup

From the repository root:

```bash
cd mobile
```

If you use nvm, install and select the project's Node version. If nvm is not installed, skip these two commands and make sure `node --version` reports Node 24:

```bash
nvm install
nvm use
```

Install JavaScript dependencies and create your local environment file:

```bash
npm install
cp .env.example .env
```

Edit `mobile/.env` to set the backend URLs. For the iOS Simulator on the same Mac:

```env
EXPO_PUBLIC_API_URL=http://127.0.0.1:8000/api
EXPO_PUBLIC_WS_URL=ws://127.0.0.1:8000
```

The `.env` file is local configuration and should not be committed. The `.env.example` is a template. For a physical iPhone, replace `127.0.0.1` with your Mac's Wi-Fi IP address and ensure both devices are on the same network. For hosted backend URLs use `https://` and `wss://`.

## Start the app in Xcode's iOS Simulator

1. Start Django from the repository's `backend/` folder. For the iOS Simulator, Django can listen on loopback (`127.0.0.1`). Keep it running on port 8000. The backend's migrations must already be applied.
2. Make sure an iOS Simulator device is booted. Open the **Simulator** app from Xcode's **Xcode → Open Developer Tool → Simulator** menu. In Xcode versions that use Device Hub, use the available iOS Simulator device there. You can also list devices with:

   ```bash
   xcrun simctl list devices available
   ```

3. From the repository root, run the native development build:

   ```bash
   cd mobile
   npx expo run:ios --device
   ```

   If prompted, choose the booted iPhone Simulator (for example, **iPhone 18 Pro**). Expo generates the iOS project from `app.json`, builds it with Xcode, installs the app, and opens it in the simulator. The app is named **Convo**.

   To target a particular simulator by name, use `npx expo run:ios --device "iPhone 18 Pro"`.

4. To start Metro separately or after the first build, use:

   ```bash
   npx expo start --dev-client
   ```

   The native app connects to Metro for JavaScript during development. Keep the Metro terminal running while using the app. Use the development-build option in the Expo terminal; this project is run as a native app and does not require installing Expo Go. If Expo asks to launch a simulator, press `i` or run `npx expo run:ios --device`.

The project enables iOS scene lifecycle support through `expo-build-properties` in `app.json`. This is required for the iOS 27/Xcode 27 simulator used by this project. The `ios/` folder is generated by Expo Continuous Native Generation and is ignored by Git; do not hand-edit it. Change native configuration in `app.json` or an Expo config plugin, then regenerate/rebuild as described below.

### Build/rebuild after native changes

After changing native dependencies or native app configuration, regenerate the generated iOS project and rebuild:

```bash
cd mobile
npx expo prebuild --clean --platform ios
npx expo run:ios --device
```

`prebuild --clean` recreates the generated `ios/` directory. It does not remove your JS source, assets, or `.env`, but any manual edits in generated native files will be lost. Normal JS/React screen changes are delivered by Metro and do not require a native rebuild.

## Android

Android requires Android Studio with an Android SDK and an available emulator, or a connected Android device. The Android emulator reaches the Mac's backend using `10.0.2.2`, not `127.0.0.1`. Set `mobile/.env` accordingly:

```env
EXPO_PUBLIC_API_URL=http://10.0.2.2:8000/api
EXPO_PUBLIC_WS_URL=ws://10.0.2.2:8000
```

Start an emulator, then from `mobile/` run:

```bash
npx expo run:android
```

For a physical Android or iPhone, use your Mac's local Wi-Fi IP instead. Start the backend bound to `0.0.0.0`, allow that host/origin in `backend/.env`, and connect both devices to the same Wi-Fi. See the root README for the backend environment settings.

## Useful mobile commands

Run these from `mobile/`:

```bash
npx expo start --dev-client       # Start Metro for the installed native development app
npx expo run:ios --device         # Build/install/open iOS app
npx expo run:android              # Build/install/open Android app
npx expo prebuild --clean --platform ios  # Recreate generated iOS project
npx expo lint                     # Lint the mobile app
npx tsc --noEmit                  # Check TypeScript/JS types
npx expo-doctor                   # Diagnose Expo config/dependency issues
```

If you change `mobile/.env`, stop and restart Expo so it reloads the public URL settings:

```bash
npx expo start --dev-client --clear
```

`EXPO_PUBLIC_*` values are embedded in the client bundle. Never put secrets, private API keys, or credentials in them.

## Troubleshooting

- **App opens then crashes on iOS 27:** confirm `expo-build-properties` is installed and `app.json` contains `ios.enableSceneSupport: true`; rerun the clean iOS prebuild and simulator build above.
- **Node engine (`EBADENGINE`) warnings:** select Node 24 (`nvm use` if you use nvm), then reinstall dependencies with `npm install`. nvm is optional; Node 24 is the required runtime version.
- **Cannot connect to backend:** confirm Django is running, the API URL is reachable from the target device, and the API path ends in `/api`. Simulator uses `127.0.0.1`; Android emulator uses `10.0.2.2`; a physical phone uses the Mac Wi-Fi IP.
- **WebSocket is rejected:** check the WebSocket URL (`ws://` for local HTTP or `wss://` for HTTPS), backend allowed origins, and that Daphne is running the ASGI application on the expected port.
- **Redis errors:** Redis is optional. If `REDIS_URL` is set in `backend/.env`, Redis must be running; otherwise the backend uses the in-memory Channels layer for a single backend process. See root README for Docker Compose commands.
- **Generated iOS project seems stale:** run `npx expo prebuild --clean --platform ios`, then `npx expo run:ios --device`.

For the full project command reference, backend and Redis setup, routes, and web development, see the repository [README](../README.md).
